# 家谱 PC 端软件 · 需求文档

- 版本：v0.3
- 日期：2026-11-12
- 状态：需求与界面原型（左侧固定菜单布局）均已确认，M1 编码进行中

---

## 1. 项目概述

| 项 | 说明 |
|---|---|
| 项目名称 | 家谱管理软件（通用名称） |
| 产品形态 | Windows PC 桌面应用（Win10/11 64 位优先，架构上保留跨平台能力） |
| 目标用户 | 家族修谱人员、普通家族成员 |
| 核心价值 | 数字化录入与管理家族成员、世系关系，支持字辈/支系管理、图谱展示、多排版 PDF 出谱，数据完全本地化并预留云同步 |
| 使用方式 | 单机离线使用，无需注册登录；**同时仅打开一份家谱**，切换式管理 |
| 数据规模 | 单谱约 **2,000 人**（性能设计留有余量） |

## 2. 功能需求

优先级定义：P0 = 首期必须；P1 = 首期应有；P2 = 后续迭代。

### 2.1 家谱成员录入（P0）

- 成员字段：
  - 基本信息：姓名、性别（男 / 女 / 未知，**男女完全平等，女性成员同样可作为世系节点向下延续后代**）、字 / 号、出生日期、卒日期、在世状态、照片、生平简介、备注
  - **日期支持公历与农历双制**：录入时选择历法，农历以干支年 + 月 + 日（如"辛卯年五月初六"）存储，展示时公历农历并列（P0）
  - 行第（兄弟姐妹中排行）、世代（第几世，自动推导 + 可手动修正）
- 亲属关系：
  - 父母类型：**生父 / 生母、养父 / 养母、继父 / 继母、嗣父 / 嗣母（过继）、兼祧父 / 兼祧母**（P0）
  - 过继：记录本生父母与嗣父母双系关系，世系图上以虚线区分
  - 兼祧：一子承两房，允许同时挂接主承父系与兼祧父系，标记主承关系；世系与 PDF 中均标注"兼祧"
  - 配偶：支持多任配偶（原配、继配等），记录婚配状态；配偶双方互相挂接
  - 子女：支持排序；同一对父母的子女自动归组
- 录入方式：表单录入 + 快速连续录入（"保存并录下一位"）；从任意成员出发"添加父亲 / 母亲 / 配偶 / 子女"
- 成员管理：搜索（姓名 / 字辈 / 支系）、编辑、删除（软删除，可恢复 / 撤销）、重复成员提示
- 校验：关系环路检测（禁止出现自己是自己祖先等非法关系）；兼祧 / 过继关系完整性提示

### 2.2 字辈管理（P0）

- 字辈序列维护：按"字辈诗"录入（如"国正天心顺，官清民自安"），逐字对应世代
- 支持全家谱统一字辈，也支持按支系各自字辈
- 字辈与世代对照表展示、编辑、插入 / 删除字（后续世代自动顺延）
- 录入成员时按当前世代自动推荐字辈用字；姓名与字辈不符时给出提示（可忽略，不强制；母系外姓成员不校验）

### 2.3 支系管理（P0）

- 支系（房）树：以始祖或任意成员为根划分支系，支系可多级嵌套
- 支系属性：名称（如"长房""二房"）、开基祖、排序、简介
- 成员归属：默认按父系自动推导所属支系，允许手动调整；兼祧成员可标注双重房支归属
- 按支系筛选成员、统计人数；支系合并 / 拆分（P1）

### 2.4 导出 PDF · 多排版模式（P0）

首期三种排版（已确认）：

1. **宝塔式吊线图**：世系自上而下如宝塔展开，连线表达父子关系，配偶并列，过继 / 兼祧虚线标注
2. **欧式横表（五世一表）**：表格横排，每表五代，表间世代衔接，适合世系总览
3. **苏式垂珠体（竖排）**：竖排右起，世代为列、人名为珠，传统线装书风格

后续迭代（P1）：人物传记式、名录简表式。

- 导出范围：整谱 / 指定支系 / 指定世代区间 / 勾选成员
- 页面设置：纸张（A4 / A3 / B5）、横竖向、页边距、正文字体字号
- 自动编排：封面（谱名、堂号、修谱时间）、目录、字辈对照页、页眉页脚（谱名 + 页码），均可选
- 中文字体嵌入，保证任何机器打开不乱码；导出前预览

### 2.5 成员关系图谱（P0）

- 交互式世系树：缩放、平移、按支展开 / 折叠
- 视图模式：全谱图 / 以某成员为中心的祖先视图 / 后代视图
- 节点展示：姓名、生卒年、世代、头像（可选）；单击查看详情，双击进入编辑
- 配偶并列显示、多任配偶区分；子女按行第排序；过继 / 兼祧以虚线 + 标注区分
- 搜索定位：输入姓名自动跳转并高亮
- 布局：纵向树、横向树（P1：扇形 / 环形）
- 图谱导出为 PNG 图片（P1）

### 2.6 数据本地化存储 · 预留云端同步（P0 本地 / P2 云同步）

- 本地存储：SQLite 数据库 + 本地照片目录，存放于用户数据目录，完全离线可用
- 每份家谱独立一个数据库文件，便于拷贝与迁移
- 云同步本期**不实现**，但架构预留：
  - 主键使用 UUID，记录 updatedAt 版本号与软删除标记
  - 数据访问层抽象，变更日志（change log）表，后续可对接 WebDAV / 自建同步服务（协议待定）

### 2.7 数据备份与恢复（P0）

- 手动备份：一键将数据库 + 照片打包为单个备份文件（`.zip` 封装，含格式版本清单）
- 自动备份：每次启动 / 每日首次写入时自动备份，保留最近 N 份（默认 10，可配置）
- 恢复：选择备份文件 → 校验完整性 → 恢复前自动备份当前数据 → 还原
- 备份文件可跨机器拷贝恢复
- 通用格式导入 / 导出（JSON）；GEDCOM 兼容为 P2（本期不做）

### 2.8 多家谱管理（P0）

- 家谱列表页：创建、打开、重命名、复制、删除（删除需二次确认 + 建议先备份，支持撤销）
- **同时仅打开一份家谱**，打开新谱即切换当前谱
- 每份家谱数据完全独立：成员、字辈、支系、导出设置、皮肤
- 家谱属性：谱名、姓氏、堂号、始祖、修谱人、修谱时间、简介
- 启动进入家谱列表 / 最近打开

### 2.9 界面皮肤切换（P0）

- 内置主题 ≥ 3 套：浅色现代、深色、古典中国风（宣纸底色 + 赭石 / 墨色点缀），另提供"跟随系统"
- 即时切换无需重启；全局默认 + 可按家谱单独记忆
- 基于 CSS 变量的主题机制，后续可扩展自定义主题（P2）

### 2.10 安装目录与数据目录自定义（P0，2026-11-12 新增确认）

- **安装目录可自定义**：NSIS 安装包采用非一键模式（`oneClick: false` + `allowToChangeInstallationDirectory: true`），安装向导中用户可自由选择安装路径；默认 per-user 安装，无需管理员权限
- **数据存储目录可自定义**：
  - 默认数据目录：`%APPDATA%/jiapu/genealogies`（用户数据目录）
  - 设置页提供"更改数据目录"：选择新目录 → 校验可写 → **迁移已有家谱数据**（复制库文件与照片到新目录，原数据保留不删除）→ 切换生效
  - 引导配置 `config.json`（记录当前数据目录、全局皮肤等）固定存放于 `%APPDATA%/jiapu/`，不随数据目录迁移
  - 每份家谱一个独立子目录：`<数据目录>/<家谱ID>/genealogy.db` + `photos/`
  - 数据目录不可写 / 不存在时给出明确错误提示，不静默回退

## 3. 非功能需求

| 类别 | 指标 |
|---|---|
| 性能 | 单谱 2,000 人量级：列表 / 搜索即时响应；图谱虚拟化渲染，全谱图流畅（设计余量至 1 万人） |
| 启动 | 冷启动 ≤ 3 秒 |
| 数据安全 | 写入事务保证一致性；异常退出不丢数据；备份文件完整性校验 |
| 易用性 | 全中文界面；录入支持键盘流转；删除类操作可撤销 |
| 可维护性 | 数据层 / 业务层 / UI 分离；同步、导出、主题均为可插拔模块 |
| 交付 | Windows 安装包（NSIS），含自动更新预留（P2） |

## 4. 数据模型（草案）

| 表 | 关键字段 |
|---|---|
| genealogy 家谱 | id(uuid), name, surname, hall_name(堂号), ancestor_id, description, created_at |
| member 成员 | id(uuid), genealogy_id, name, gender, courtesy_name(字号), birth_date, birth_lunar, death_date, death_lunar, alive, generation(世代), branch_id, bio, photo_id, sort_order(行第), updated_at, deleted |
| relation 关系 | id, genealogy_id, type(parent_child / spouse), from_id, to_id, subtype(生/养/继/嗣/兼祧、原配/继配), is_primary(兼祧主承标记), sort_order |
| generation_char 字辈 | id, genealogy_id, branch_id(可空=全谱), generation, char, seq |
| branch 支系 | id, genealogy_id, parent_id, name, root_member_id, sort_order, description |
| media 照片 | id, genealogy_id, file_path, hash |
| change_log 变更日志 | id, genealogy_id, entity, entity_id, op, payload, created_at（云同步预留） |
| setting 设置 | genealogy_id, key, value（皮肤、导出偏好等） |

关系说明：
- 过继成员同时存在本生父母（subtype=生）与嗣父母（subtype=嗣）两组 parent_child 记录
- 兼祧成员存在主承父系（is_primary=1）与兼祧父系（subtype=兼祧, is_primary=0）记录，图谱 / PDF 均双系呈现

## 5. 技术方案（已确认）

| 层 | 选型 | 说明 |
|---|---|---|
| 桌面框架 | **Electron** | 生态成熟，Node 生态直接可用 |
| 前端 | **Vue 3 + TypeScript + Vite** | |
| 本地数据库 | **node:sqlite（Electron 内置）** | 原计划 better-sqlite3；因构建机无 Python/VS 原生编译工具链，改用 Electron 内置 Node（≥22.13）自带的 node:sqlite，同为同步 API + 完整 SQL/事务能力，零原生依赖、免重建 |
| 关系图谱 | **AntV G6** | 支持树图布局、展开折叠、大数据量渲染 |
| PDF 导出 | **HTML/CSS 排版模板 + Electron printToPDF** | 中文排版能力强，三种排版 = 三套模板 |
| 农历 | **lunar-typescript** | 公农历互转、干支纪年 |
| 打包 | electron-builder（NSIS 安装包） | |
